## K별 학습 스텝 수 (수렴 탐색, 2026-11-17)

8호스트, 스텝 한도 100, M1(보상만), 시드 3개.

출처:
- `results/phase1/converge/2m/steps_to_converge.csv`, `curve_bins.csv`
- 그림 `results/phase1/converge/2m/learning_curves.png` (1M 실행은 `converge/1m/`)
- K=4는 `results/phase1/runs/M1_h8_K4_seed*/episodes.csv`

| K | 학습 풀 solve rate ≥ 90% 첫 도달 | solve rate 평탄 시작 | 에피소드 길이·비용 평탄 | 권장 스텝 |
|---|---|---|---|---|
| 4 | 100k~150k | 200k | 200k~250k (300k까지만 관측) | 500k |
| 16 | 300k~350k | 350k~500k | 약 750k | 1M |
| 32 | 450k~550k | 550k~650k | 2M에서도 미세 감소 | 2M |

권장 스텝은 solve rate가 아니라 에피소드 길이와 에피소드당 비용이 평탄해지는 시점을 기준으로 정했다. solve rate는 일찍 100%에 붙지만, 그 뒤에도 정책은 짧아지고 비용이 줄어든다. 이 연구가 재는 것이 비용이므로 그것이 멈춘 뒤를 기준으로 한다.

시드 평균 학습 곡선:

- K=16
  - 750k: 길이 8.00, 비용 1.295
  - 1M: 7.89, 1.277
  - 2M: 7.78, 1.297
- K=32
  - 1M: 길이 9.20, 비용 1.104
  - 1.5M: 8.41, 0.994
  - 2M: 8.14, 0.970
- K=4: 300k까지만 돌렸고 마지막 두 구간(250k, 300k)에서 평탄했다. 여유를 두어 500k로 잡았다.

같은 K 안에서는 모든 방법이 같은 스텝 수를 쓴다.

## 티어 1 예상 (권장 스텝 기준, 2026-11-17)

티어 1 = 학습 방법 5개(M1, M2a, M2b, M3, M4) × K∈{4, 16, 32} × 시드 10 = 150 run. M0은 run당 약 4초라 무시한다.

run당 시간은 3개 병렬 실행에서 잰 값이다(`results/phase1/converge/2m/*/done.json`).

- K=16 2M: 학습 640~644초, 전체 668~672초 (초당 약 3110 스텝). 측정 중 약 1분간 다른 짧은 테스트가 함께 돌았다.
- K=32 2M: 학습 598~602초, 전체 627~632초 (초당 약 3340 스텝).
- run당 평가 시간: 약 28~30초.
- 1M 실행과 Phase 1 K=4 실행은 중단 전 작업과 겹쳐 프로세스 6개가 동시에 돌았으므로 시간 추정에 쓰지 않았다.

| K | 스텝 | run당 예상 | run 수 | 3개 병렬 소요 |
|---|---|---|---|---|
| 4 | 500k | 약 3분 (500k / 3200 + 25초) | 50 | 약 50분 |
| 16 | 1M | 약 6분 (1M / 3110 + 30초) | 50 | 약 1.6시간 |
| 32 | 2M | 약 10.5분 (측정값) | 50 | 약 2.9시간 |
| 합계 | | | 150 | **약 5.4시간** |

- 계산: run당 시간 × 50 / 3.
- 반영되지 않은 것: M3(비용 critic)와 M4(action mask)의 오버헤드.
  - 20% 늘면 약 6.4시간으로, 하룻밤(8시간) 안이다.
  - run 하나는 최대 약 10.5분으로 20분 한도 안이다.
- 티어 2(시드 10 → K=16 추가 등)는 계획이 바뀌었으므로 Phase 3 전에 다시 계산한다.

## (이전) Phase 1 시점 계산 — 재현성 버그 수정 전 측정, 참고용

티어 1 = 학습 방법 5개(M1, M2a, M2b, M3, M4) × K∈{4, 16, 32} × 시드 10 = **150 run**. M0은 학습이 없어 run당 약 3초다.

실측 (`results/phase1/runs/*/done.json`, `results/phase1/probe_k/*/done.json`, 3개 병렬 실행 중):

- 직접 구현 PPO 학습 속도: 프로세스당 초당 약 3500~3590 스텝 (환경 8개, 8호스트·6호스트 모두)
- 300k 스텝 run 하나(학습 + 평가 92개 네트워크): 103~112초
- 따라서 평가와 시작 비용은 run당 약 20~25초

150 run을 3개 병렬로 돌릴 때 (산술 추정):

| run당 학습 스텝 | run당 예상 시간 | 티어 1 전체 |
|---|---|---|
| 300k | 약 1.8분 | 약 1.5시간 |
| 1M | 약 5분 | 약 4.3시간 |
| 2M | 약 10분 | 약 8.2시간 |

세 경우 모두 run당 20분 한도 안이다. 2M이면 하룻밤(8시간)을 꽉 채운다.

반영되지 않은 것: M3(비용 critic 추가)와 M4(action mask)의 오버헤드는 아직 측정하지 않았다. 스텝 수는 미확정이다. Phase 1 탐색 실행에서 K=16, 32는 300k 스텝으로 수렴하지 않았다.

## (이전) 티어 1 예상 — Phase 0 시점의 추정

가정: run당 300k 스텝, 초당 약 2700 스텝 → run당 약 2분.
50 run → 순차 약 100분, 3개 병렬이면 약 35~60분(병렬 시 속도 저하는 측정하지 않았다).
하룻밤(8시간) 예산에는 충분한 여유가 있을 것으로 보인다. 단, 다음은 반영되지 않았다:

- 직접 구현 PPO의 속도(SB3와 다를 수 있다)
- 여러 네트워크(K=4, 32)에서 학습할 때 필요한 스텝 수 — 단일 네트워크보다 많이 든다
- 비용 wrapper·관측 누적 wrapper의 오버헤드
- 평가(학습 풀 + 테스트 A/B 60개 네트워크) 시간

Phase 1에서 직접 구현 PPO로 K=4를 한 번 돌린 뒤 이 문서를 갱신해 티어별 스텝 수를 확정한다.
