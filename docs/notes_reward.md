# 보상 재설계 노트 (쉬운 설명)

계획서는 `docs/plans/REWARD_REDESIGN_PLAN.md`, 보고서 본문은 `report/reward_redesign.md`(숫자는 모두 스크립트가 채운다)에 있다. 이 노트는 단계마다 무엇을 했고 무슨 뜻인지 쉬운 말로 적는다.

## 단계 1 — 감사 (2026-11-17, 학습 없음)

실행: `python -m src.cli reward-audit`, `python -m src.cli reward-report`. 결과 파일은 `results/reward/`에 있다.

### 지금 보상은 어디서 왔나

모든 값이 NASim 시나리오 생성 함수(`ScenarioGenerator.generate`)의 기본값이다. 우리가 고른 값이 아니다.

| 항목 | 값 | 역할 |
|---|---|---|
| 목표 호스트 root | +10 | 과제 정의 (목표 자체) |
| 그 밖의 호스트 root | +1 | 보조 보상(shaping) |
| 서브넷 스캔으로 새 호스트 발견 | 호스트당 +1 | 보조 보상(shaping) |
| 모든 행동 | −1 | 과제 정의 (시간·소음의 대가) |

- "과제 정의"는 빼면 무엇이 성공이고 무엇이 효율적인지가 바뀌는 항목이다.
- "보조 보상"은 어차피 목표 보상이 결국 보상할 진척을 미리 쳐주는 항목이다.
- 이 분류는 우리 판단이다.

### 선행연구는 어떻게 했나

| 출처 | 목표 보상 | 공격 비용 | 스캔 비용 | 비목표 호스트·발견 보상 |
|---|---|---|---|---|
| NASim 손으로 짠 yaml 시나리오 | 100 | exploit 1~3 (난이도별), 권한 상승 1 | 1 | 둘 다 0 |
| NASim 자체 생성 벤치마크 | 100 | 1 | 1 | 둘 다 1 |
| 우리 (생성 함수 기본값) | 10 | 1 | 1 | 둘 다 1 |
| NASimJax | 50 | 3 | 1 | 발견 1, 비목표 호스트는 읽은 부분에 없음 |

- NASim 자체 생성 벤치마크도 목표 보상을 100으로 덮어쓰는데, 우리는 덮어쓰지 않은 함수 기본값 10을 썼다.
- NASimJax는 "정보 수집을 건너뛰는 무작정 공격을 막으려고 3:1 비율을 쓴다"고 적었다. 문장은 arXiv HTML판에서 가져왔다.

### Δ: 보상만 보면 위험한 길이 얼마나 더 버나

Δ는 "가장 많이 버는 길의 return − 비용 0으로 가장 많이 버는 길의 return"이다. 모든 정보를 아는 상태에서 NASim 상태를 끝까지 탐색해 구했다. 출처는 `results/reward/audit_optimal_paths.csv`.

| | 학습 풀 | 테스트 A | 테스트 B |
|---|---|---|---|
| Δ 평균 | 0.69 | 0.70 | 1.70 |
| Δ > 0인 네트워크 비율 | 50.0% | 53.3% | 96.7% |

- **지금 보상에서는 위험한 길의 이득이 작다.** 목표 보상이 20인데 Δ는 0~3이다.
- 학습 풀과 테스트 A는 절반 정도 네트워크에서 Δ가 0이다. 그런 네트워크에서는 안전한 길도 똑같이 번다.
- 이득은 "바로 root를 주는 risky exploit으로 권한 상승 한 번을 아끼는 것"에서 나온다.
- 계획서는 Δ > 0을 유지하라고 하므로, 새 보상도 이 이득을 남겨야 한다.

### C1(범위 밖 공격)은 "비목표 호스트 root +1" 때문인가

- **최적 경로 기준으로는 아니다.** 모든 정보를 아는 최적 경로는 92개 네트워크 중 어디에서도 C1이 필요 없다. +1을 없애도 마찬가지다. 범위 밖 호스트는 반드시 거쳐야 하는 곳도 아니고, 장악해도 이득이 없다.
- **M1의 실제 행동에서는 관련이 있어 보인다.** 학습 풀에서 M1이 낸 C1의 대부분(K=16 53.5%, K=32 73.2%)이 범위 밖 호스트에서 root를 얻어 +1을 받은 경우다.
  - 지금 비용으로는 이 행동의 보상이 0이다(+1 − 1). 그래서 보상은 이 행동을 피할 이유를 주지 않는다.
  - +1이 없으면 이 행동은 매번 −1이 된다.
  - 출처는 `results/reward/audit_m1_c1_events.csv`.
- 다만 이것은 "그 행동이 무엇을 얻었나"로 분류한 것이지 원인을 잰 것이 아니다. +1을 빼면 정말 C1이 줄어드는지는 학습해 봐야 알 수 있다(단계 3).
- 테스트 A·B의 C1은 대부분 실패한 시도다. 네트워크를 모르는 정책이 헤매며 낸 것이다.

### 검증

- 우리가 다시 계산한 보상(`RewardSpec`)은 탐색한 모든 전이에서 NASim 보상과 일치했다.
- 다시 재생한 M1의 C1 개수는 각 run의 `eval.csv`와 정확히 같았다(`results/reward/audit_m1_trace_check.csv`).

## 단계 2 — 후보 채점 (2026-11-18, 학습 없음)

실행: `python -m src.cli reward-grid`(약 10분), `python -m src.cli reward-report`. 결과는 `results/reward/grid.csv`(후보 192개, 한 줄씩), `grid_by_split.csv`, `grid_episodes.csv`, `grid_paths.csv`, `grid_pareto.png`.

### 사용자가 정한 것 (게이트 1)

- 서브넷 스캔도 다른 스캔과 같은 "정찰 비용" 하나로 묶는다. 스캔 비용이 낮고 발견 보상이 있으면 서브넷 스캔이 오히려 이득이 될 수 있다(알려진 부작용).
- "일반 전략" 기준은 로봇 B(스캔 먼저 + 범위 밖·fragile 회피). 로봇 A 점수도 남기지만 순위는 B로 매긴다.
- 점수는 γ=0.99 할인 return. PPO가 실제로 최대화하는 값이다.
- 목표 보상 {10, 100} 축, 실패한 공격 추가 벌점 {0, 2} 축을 더해 4×3×2×2×2×2 = 192개.
- "실패한 공격" = exploit·권한 상승 뒤에 대상 호스트 접근 수준이 올라가지 않은 경우. 연결·권한 오류, 서비스·OS 불일치, 이미 가진 수준으로 다시 공격한 경우가 모두 포함된다.

### 어떻게 채점했나

- 보상은 여섯 가지 개수(공격, 스캔, 새로 찾은 호스트, 목표 root, 다른 호스트 root, 실패한 공격)의 일차식이다. 그래서 각 정책을 **한 번만** 돌려 에피소드마다 할인된 개수 합을 저장하고, 후보 192개는 곱셈만으로 채점했다.
- 최적 경로는 "가장 짧은 경로"를 쓰지 않았다. 비용이 다르고 할인이 있으면 짧은 길이 꼭 가장 많이 버는 길은 아니기 때문이다. 대신 모든 정보를 아는 상태에서 NASim 상태를 끝까지 탐색해, 후보마다 "지금 상태에서 앞으로 받을 할인 return의 최댓값"을 거꾸로 계산했다. 상태는 접근 권한과 발견한 호스트가 늘어나기만 하므로 되돌아가는 고리가 없고, 그래서 이 계산은 정확하다.
- 검증:
  - 현재 보상에서 할인 없이 계산하면 단계 1 결과와 모든 네트워크에서 같다.
  - 다시 돌린 M1 에피소드는 각 run의 `eval.csv`와 에피소드 단위로 같다(성공, 걸음 수, return, C1, C2).
  - 실패 벌점을 바꿔도 최적·최적 안전 return은 하나도 변하지 않는다(최적 경로에는 실패한 공격이 없다).

### 결과 (학습 풀 32개 네트워크 평균, 숫자는 `results/reward/grid.csv`)

- **계획서의 필수 기준(로봇 B가 무작위보다 확실히 낫다, Δ > 0)은 192개 모두 통과한다.** 그래서 순위는 사실상 "암기 이득(최적 return − 로봇 B return)" 하나로 정해진다.
- **암기 이득은 0이 될 수 없다.** 로봇 B는 공격 전에 스캔해야 하고(스캔은 비용만 들고 상태를 바꾸지 않는다), 목표에 늦게 도착하므로 할인 때문에 목표 보상을 덜 받는다. 로봇 B는 에피소드당 약 24걸음, 최적 경로는 4~8걸음이다.
- 가장 작은 암기 이득:
  - 목표 10: 스캔 0.1, 공격 1일 때 4.72점(목표의 47%).
  - 목표 100: 22.73점(목표의 23%).
  - 현재 보상: 17.43점(목표의 174%).
- **Δ는 모든 후보에서 작다**(0.27~1.47점). 192개 모두 암기 이득보다 작다. 즉 어느 후보에서든 "위험한 지름길"보다 "학습 네트워크 외우기"가 더 큰 유혹이다.
- 각 축이 하는 일:
  - 스캔 비용을 낮추면 암기 이득이 크게 준다. Δ는 그대로다.
  - 공격 비용을 높이면 Δ가 커지고(위험 exploit이 공격 한 번을 아끼므로), "스캔 먼저"가 "무작정 공격"보다 더 이득이 된다. 대신 암기 이득도 조금 커진다.
  - 비목표 root 보상(+1)이 있으면 Δ > 0인 네트워크가 21.9%에서 50.0%로 늘어난다. 단계 1에서 이 보상이 M1의 범위 밖 root를 "손해 없는 행동"으로 만든다고 봤으므로, 이 축은 "갈등을 키울지"와 "C1 유인을 없앨지" 사이의 맞교환이다.
  - 목표 보상 100은 암기 이득을 목표 대비로는 줄이지만, Δ도 목표의 1% 정도로 작아진다.
  - 실패 벌점 2는 Δ를 바꾸지 않고, 로봇 B의 점수는 거의 그대로이며(B는 실패가 드물다), "스캔 먼저 − 무작정 공격" 차이를 크게 벌린다.
  - 발견 보상은 거의 영향이 없다.
- 100걸음 내내 가장 싼 행동만 하며 버티는 쪽이 최적이나 로봇 B보다 나은 후보는 없다.
- M1은 현재 보상으로 학습된 정책이라, 새 보상으로 다시 채점한 값은 "지금 행동이 몇 점인가"일 뿐 새 보상에서 PPO가 무엇을 배울지는 말해 주지 않는다. 그건 단계 3에서 본다.

### 사용자에게 올린 선택지 (보고서 3절 "Options for gate 2")

1. 목표 10, 스캔 0.1, 공격 1, 발견 0, 비목표 root 1: 목표 10 안에서 암기 이득이 가장 작은 축에 속하고, Δ는 현재와 같다. 단, 암기 이득은 여전히 목표의 절반 정도다.
2. 목표 100, 스캔 0.1, 공격 1, 발견 1, 비목표 root 1: 목표 대비 암기 이득이 가장 작은 축이다. 단, Δ가 목표의 1%이고, return 규모가 지금의 약 10배라 우리 PPO(보상 정규화 없음)에서 학습이 잘 될지는 단계 3에서 봐야 한다.
3. 선행연구 비율(NASimJax 스캔 1 : 공격 3), 목표 100, 비목표 root 0: 근거가 있고 "스캔 먼저"의 이득이 크다. 단, 셋 중 암기 이득이 점수로 가장 크고, Δ > 0인 네트워크가 21.9%로 적다.

각 선택지에 실패 벌점 2를 붙일지는 따로 고를 수 있다.
